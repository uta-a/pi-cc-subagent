# pi-cc-subagent

Pi 用のサブエージェント拡張。**公式 Claude Code 2.1.19 / 2.1.63 の npm 配布コードを実際に確認**し、サブエージェントのターミナル表示を Pi のレンダラーで再実装しています。拡張の実行に Claude Code の環境や契約は不要です。

## 導入

Pi 1.5.1 で動作確認。

```bash
# このディレクトリで、一度だけ試す
pi -e ./src/index.ts

# GitHub の最新 main を使う（タグ・コミットには固定しない）
# ステータスラインも併せて導入すると縦表示・右寄せ統計が有効になる
pi install git:github.com/uta-a/pi-cc-statusline
pi install git:github.com/uta-a/pi-cc-subagent
```

インストール後は起動中の Pi で `/reload`。既存の `pi-subagents` とツール名が衝突しないよう、`cc_subagent` という名前で登録します。

更新時は次を実行し、Pi で `/reload` します。`latest` というタグではなく、Git の既定ブランチ `main` の最新コミットへ更新する設定です。

```bash
pi update git:github.com/uta-a/pi-cc-statusline
pi update git:github.com/uta-a/pi-cc-subagent
```

## 使い方

```text
/cc-agent Explore 認証処理の入口とセッション管理の流れを調べて
/cc-agent Plan 認証処理のリファクタリング案を作って
/cc-agent general-purpose 指定した不具合を修正してテストして
```

このコマンドは親モデルに `cc_subagent` の呼び出しを依頼します。親モデルがタスクと結果を取りまとめ、サブエージェントは独立した会話履歴で実行します。作業ディレクトリと権限チェックを引き継ぎ、モデルと effort はタスクごとに選択します。`general-purpose` は親のシステム指示全体を引き継ぎます。`Explore` / `Plan` は取得済みのプロジェクトコンテキストがあれば軽量な専用プロンプトを使います（詳細は後述）。会話履歴自体は引き継がないため、タスクには必要な情報を含めてください。

モデルから使う場合：

```json
{
  "description": "認証処理の調査",
  "prompt": "src/auth 配下の認証フローを調査し、関連ファイルと問題点を報告してください。",
  "subagent_type": "Explore",
  "name": "researcher"
}
```

`name` は省略可能な表示名です。一覧・詳細パネル・履歴内の行で、種類名（`Explore` / `Plan` / `worker`、履歴では `Task`）の代わりに表示します。改行などの制御文字は空白に置き換え、24文字までに切り詰めます。空白だけの場合は種類名を使います。表示専用のため、権限やモデル選択は変わりません。

並列実行：

```json
{
  "tasks": [
    { "description": "認証処理の調査", "prompt": "認証の入口を調べて", "subagent_type": "Explore" },
    { "description": "テストの調査", "prompt": "認証テストの不足を調べて", "subagent_type": "Explore" }
  ]
}
```

最大8タスク、同時実行4。並列タスクに同じファイルを編集させないでください。通常の前景実行では、`Esc` による親のキャンセルを子のモデル呼び出しとツール呼び出しにも伝播します。

### バックグラウンド実行

**種類を問わず、空きがあれば既定でバックグラウンド実行します。** `general-purpose`（種類未指定を含む）も対象です。 起動した子の表示名・タスク説明だけを返し、親は即座に作業を続けられます。`run_in_background` はトップレベルで指定し、呼び出し全体（単一タスクでも `tasks` 配列でも）に適用します。

| `run_in_background` | 動作 |
|---|---|
| 省略（既定） | 全種類で、呼び出し全体を収容できる空きがあれば背景実行。空きが足りなければ、何も拒否せず前景で完了を待ちます |
| `false` | 常に完了を待つ（結果をすぐ次の判断に使いたいとき） |
| `true` | 背景実行を必須にする。下記の条件を満たさなければ何も起動せずエラー |

```json
{
  "run_in_background": true,
  "tasks": [
    { "description": "認証処理の調査", "prompt": "認証の入口を調べて", "subagent_type": "Explore", "name": "researcher" },
    { "description": "改善案の検討", "prompt": "認証設計の改善案を検討して", "subagent_type": "Plan" }
  ]
}
```

- 背景タスクは別々の呼び出しも合計して**最大4件、そのうち書き込み可能な `general-purpose`（種類未指定を含む）は最大2件**。`tasks` の各タスクを1件と数え、呼び出し全体の枠をまとめて予約します。`true` を明示して空きが足りなければ全件を起動前に拒否し、省略時は完了を待つ実行に切り替えます。待機キューはなく、終了後に再度呼び出せます。この上限は前景実行とは別枠です。中断要求後も処理が戻るまでは枠を使用します。
- 進捗はステータスラインと ↑↓・Enter のライブ詳細で確認できます。即時のツール結果は「起動済み」の固定表示で、進捗表示にはしません。
- 全タスクが終了すると、成功・失敗・中断をまとめた **1件の完了メッセージ**（`cc-subagent-result`）を親へ送ります。`followUp` として現在の親の作業が終わってから届け、待機中なら応答を開始します。履歴は通常の `Done (...)` 行に折りたたみ、`Ctrl+O`（ツール展開キー）で結果を展開できます。
- 親のターン終了や `Esc` では背景タスクを止めません。**`/cc-agents-stop`** で背景タスクをすべて中断、**`/cc-agents-stop researcher`** のように表示名（重複時は `Explore-2` 等）を渡すと該当の子だけ中断します。中断結果は `Interrupted`。前景タスクには影響しません。
- セッション終了・切り替え・拡張の再読み込みでも背景タスクを中断し、その後の完了メッセージは送りません。背景タスクの再開はできません。
- 背景タスクの使用量は**親セッションの合計には加算されません**。子ごとの累積トークン数・コストはライブ詳細、使用量の内訳は完了メッセージの `details` に残します。終了済みのツール結果に使用量を後付けする Pi API は使っていません。

### 背景 writer のファイル競合ガード

背景の書き込み可能な子が `write` / `edit` に渡したパスは、実行前にその子がロックし、成功・失敗・中断で子が終了するまで保持します。別の背景 writer が同じパスを指定するとツールを実行せず、保持者名と「再試行せず競合を報告する」エラーを返します。

- 親のトップレベルの `write` / `edit` も背景の子のロックを検査します。競合時は結果メッセージを待つか、`/cc-agents-stop <表示名>` で停止するよう案内します。停止要求だけでは解除せず、子の終了時に解除します。
- 背景 writer が1件でもいる間、親の `write` / `edit` は実行前に一時予約し、成功したパスを `main` のロックとして保持します。失敗した一時予約は解除し、最後の背景 writer が終了すると親のロックをすべて解除します。セッション終了時もすべて解除します。
- パスは先頭の `@` を除き、作業ディレクトリに対する絶対パスとして比較します。シンボリックリンク・ハードリンク等の別名は同一視しません。
- **`bash` による変更、外部プロセスやユーザーの編集は追跡できません。** 親が待機する前景の子もこのロックの対象外です。したがって前景の子と背景 writer の競合も防げません。Pi のファイル変更キューや権限フックはそのまま通しますが、これはサンドボックスや完全な排他制御ではありません。

背景 writer の起動後は、親も同じファイルの編集を避け、完了メッセージを待って結果を取り込んでください。同じ作業の再起動やポーリングは不要です。

## 表示

```text
● Explore(認証処理の調査) (ctrl+o to expand)
  ⎿  Read(src/auth.ts)
     Read(src/session.ts)
     Search(validateSession)
     +1 more tool use (ctrl+o to expand)

● Explore(認証処理の調査) (ctrl+o to expand)
  ⎿  Done (7 tool uses · 12.4k tokens · 23s)

● Running 2 Explore agents… (ctrl+o to expand)
   ├─ 認証処理の調査 · 7 tool uses · 12.4k tokens
   │  Read(src/auth.ts)
   └─ テストの調査 · 3 tool uses · 8.2k tokens
      Read(test/auth.test.ts)
```

- 通常表示は直近3件の進捗だけ。完了後は統計に折りたたみ。
- `Ctrl+O` で `Prompt:`、実行履歴、`Response:` を展開。キーを変更している場合は実際の設定を表示。
- 低いターミナルでは `In progress…` に省略。
- 背景ボックスは使わず、`●` と `⎿`、並列ツリーのインデントを再現。
- 配色は Pi の現在のテーマを使用。

**API 呼び出しなしのデモ：** `/cc-subagent-demo`。`[demo]` 付きの架空データを履歴に表示します。

## ステータスライン下のエージェント表示

実行中は、ステータスラインの下に親・子エージェントを縦に表示します。MCP など他の拡張ステータスとの間には空行を1行入れます。

```text
Opus … · Context …

● main
○ Explore  ホームの git リポジトリ概要調査                  6s · ↓ 26.4k tokens
○ worker   テストを実行                                  3s · ↑ 2.1k tokens
```

- 選択中の行は白・太字の `●`、他の行は灰色の `○`。子の役割・タスク名・経過時間・トークン数を表示します。
- 統計は実際の描画幅に合わせて右寄せし、長いタスク名を先に省略します。狭い画面では統計を省略します。
- 表示名は `name`、未指定なら種類名。同じ表示名の子は `Explore-2`、`researcher-2` などで区別。先に始まった子が完了しても、残った子の番号は変わりません。
- 待機中・完了・失敗・中断済みの子は非表示。全実行終了で行を消します。中断要求を受けて終了処理中の子は、処理が戻るまで表示される場合があります。
- 別々の `cc_subagent` 呼び出しも合成し、最大8件と残り件数を表示。
- `ctx.ui.setStatus()` を使用し、既存のフッターや他拡張のステータスは上書きしません。縦表示には、改行対応した `pi-cc-statusline` を併用してください（同プロジェクトの `extension/status-rows.ts`）。Pi 標準フッターは改行を空白に変換するため横表示になります。拡張ステータスを描画しない独自フッターでは表示されません。
- ステータス表示は TUI のみ。通常画面・全画面の両方で確認済みです。

**表示だけ試す：** `/cc-subagent-status-demo`（10秒で消去）。即時消去は `/cc-subagent-status-demo off`。実行中はデモを開始できません。実タスク開始時もデモを消去します。

### ↑↓・Enter の操作

入力欄が空のときは **↓**（または Shift+↓）で **チャット → main → sub1 → sub2 …** の順に移動します。**↑** は逆順で、先頭・末尾では折り返しません。main から↑でチャットへ戻り、最後の子から↓を押してもチャットへ飛びません。チャットにいるときの↑は通常のプロンプト履歴として使えます。入力欄に文章がある場合や、権限確認・別の選択画面にフォーカスがある場合は、その入力操作を奪いません。

- **Enter**：選択した子のライブ詳細を開きます。main ではプレビューを開かず、元の会話へ戻ります。
- 詳細内の **↑↓**：表示対象を切り替え、最後の子で↓を押しても末尾に留まります。main に移動した時点でプレビューを閉じて main の選択を維持し、もう一度↑でチャットへ戻ります。
- **PgUp / PgDn**：詳細をスクロールします。
- **Enter / Esc**：詳細を閉じて入力欄へ戻ります。閉じる操作で子を中断しません。
- **`/cc-agents`**：選択中の子、または最初の実行中の子の詳細を開きます。

子の詳細には使用モデル・effort・profile、タスク、現在のモデル待機・ツール実行、活動履歴、生成中の応答、最終結果を表示します。main では通常の Pi の会話をそのまま表示します。完了した子を開いていた場合は最終状態を確認でき、↑↓で現在の実行一覧に戻れます。

公式 2.1.63 の `cSq` / `e16` / `jb` の選択・表示・復帰状態を参考にした **Pi 用の読み取り専用詳細パネル** です。CC のネイティブな会話トランスクリプト差し替え、チーム機能、Escによる子の中断、管理画面のkill操作は移植していません（背景タスクは `/cc-agents-stop` で中断できます）。画像の縦配置と plain ↑↓ 操作は依頼に合わせた仕様です。

## タスク別のモデル・effortとコスト制御

`model` / `effort` / `profile` は単一タスクにも `tasks` 配列の各項目にも指定できます。未指定時は追加の分類用APIを呼ばず、タスク種別・リスクキーワードと利用可能なモデル一覧で振り分けます。

| profile | 用途・既定 effort | モデルターン上限 | ツール上限 | 1応答 / 累計出力トークン上限 |
|---|---|---:|---:|---:|
| `quick` | 軽い探索・誤字修正、`minimal` | 6 | 12 | 2,048 / 4,096 |
| `balanced` | 通常の実装、`low` | 12 | 24 | 4,096 / 12,000 |
| `deep` | 設計・難しい監査、`medium` | 20 | 48 | 8,192 / 24,000 |

- 自動選択は、quickなら利用可能な Haiku/mini/flash 系、balancedなら親がOpus/軽量系の場合にSonnet系、deepなら親がSonnet/軽量系の場合にOpus系を優先します。現在のproviderを優先し、同じprovider・系統では新しいIDを優先します。GPT等の性能序列が不明なモデルを名前だけで格付けしません。
- 対応モデルがなければ親モデルを維持します。自動選択はセッションの scoped models を尊重します。
- `model: "provider/id"` で明示、`model: "inherit"` で親を維持できます。利用不可・曖昧な明示指定は黙って別モデルへ変更せずエラーにします。
- `effort` は `auto` / `off` / `minimal` / `low` / `medium` / `high`。非推論モデルでは `off`、小さい残り出力予算では推論を切ります。実際のprovider側の対応レベルへの変換はPiに任せます。
- `profile: "auto"` が既定。`Explore` は通常quick、`Plan` はdeep。複雑な監査等はdeepへ切り替えます。必要なら呼び出し側でprofileを明示してください。
- 単価や契約残量をリアルタイム比較する最安保証ではありません。別providerへ自動選択される場合もあります。固定したい場合は `model: "inherit"` を使ってください。

```json
{
  "tasks": [
    { "description": "関連ファイルを探す", "prompt": "関連ファイルだけ報告", "subagent_type": "Explore", "profile": "quick", "effort": "minimal" },
    { "description": "競合状態を検証", "prompt": "競合の再現条件と安全な修正方針を検証", "subagent_type": "Plan", "profile": "deep", "effort": "medium", "model": "inherit" }
  ]
}
```

ツール利用は検索→絞り込んだ範囲の読み取りを優先し、独立した読み取りを1モデル応答にまとめ、重複探索・不要な検証の再実行を避けるよう指示します。ツール結果はprofileごとに4/8/12 KiBに制限します。

- **`read` の行数上限**：子が `limit` を指定しないと200行、指定しても最大500行までです。続きがある場合は Pi の `read` が「`offset=` で続きを読める」と案内するため、必要な部分だけ追加で読めます。
- **重複呼び出しの省略**：`read` / `grep` / `find` / `ls` を同じ引数で再度呼ぶと実行せず、「同じ結果を既に返した」とだけ返します。パスは絶対パスに正規化して比較します。内容を再送しないため、権限チェックを迴回して新しい情報を渡すことはありません。その子が `bash` / `write` / `edit` を実行すると記録を消去し、失敗した呼び出しは記録しません。ただし、他の子やユーザーが別途変更したことは検知できません。その場合は `offset` など引数を変えると再実行されます。
ターン・ツール呼び出し・累計出力の予算に達すると、そのバッチの残りのツールは実行せずエラーを返し、**ツール禁止（`toolChoice: "none"`）・最大1,024トークンの最終報告を1回だけ**要求します。この1ターン分は通常のターン・出力予算を少し超過できます。状態は `failed` のまま、予算エラーと未完了部分を含む報告を親へ返します。報告要求自体が失敗すれば予算エラーだけを返します。中断は即時停止し、報告要求を追加しません。勝手な再試行・モデル昇格はしません。

UIの通常更新は詳細表示・スナップショットとも毎秒1回に抑え（開始・終了などの状態変化は即時反映）、フッターの時計更新だけでは履歴を複製しません。mainの本文を別途追跡・描画する処理も省いています。

### 子のプロンプトと報告

`before_agent_start` で最新のプロジェクトコンテキストを作業ディレクトリとともに保持します。パスと本文の合計で最大32 KiB、先頭からファイル単位で収まる分だけを採用し、省略があれば明記します。`Explore` / `Plan` は短い基本指示、作業ディレクトリ・日付、役割・ツール・予算のルール、パス付きの `<project_context>` だけを使い、親のシステムプロンプト全体は含めません。取得失敗・採用ファイルなし・作業ディレクトリ不一致なら従来どおり親のプロンプト全体に子の指示を追加します。`general-purpose` は安全性のため常に従来方式です。

提供元によっては、親のプロンプトを含まないシステムプロンプトを受け付けません。たとえば `pi-claude-bridge` は、親セッションで記録したプロンプトを含まない要求を `prompt-capture` エラーで拒否します。絞ったプロンプトの初回リクエストが出力ゼロでエラーになった場合は、親のプロンプト全文で1回だけ再試行します。そのため `claude-bridge` 経由では従来どおり動きますが、プロンプトを絞る効果はありません（拒否はローカルで即座に返り、トークンは消費しません）。

- `Explore`：タスクのパス・シンボルから狭い検索と必要範囲の読み取りを行い、コード引用は約5行まで。`## Findings`（パス・行範囲付き）、`## Start here`、`## Gaps` で報告。
- `Plan`：読み取り専用で、`## Recommendation`、`## Steps`、`## Risks`、`## Open questions` で報告。
- `general-purpose`：`## Changed files`、`## Validation`（実行コマンドと結果）、`## Open risks`、`## Next step` で報告。必要な編集をしていない、または検証失敗なら成功としません。未承認の判断が必要なら推測せず停止し、`## Needs decision` に選択肢を示します。

いずれも簡潔な報告を指示します。報告形式や内容の正しさを機械的に保証するものではありません。

## 実行・安全性の範囲

| 種別 | 使用可能なツール |
|---|---|
| `Explore` / `Plan` | `read`, `grep`, `find`, `ls` |
| `general-purpose`（既定） | 上記 + `bash`, `write`, `edit` |

親で利用可能なツールとの積集合だけを公開します。モデルが未公開ツールを要求しても実行しません。`ctx.executeTool()` を通すため、親の引数検証、権限フック、ファイル変更キューを維持します。`general-purpose` は通常の Pi と同じユーザー権限で動き、サンドボックスではありません。

**`grep` / `find` / `ls` の有効化を推奨します。** Pi の既定で有効なのは `read` / `bash` / `edit` / `write` だけです。そのままだと `Explore` / `Plan` は実質 `read` しか使えず、検索で絞り込めないため読み込みが増えます。`~/.pi/agent/settings.json` に次を追加すると、親の権限チェックを通したまま子もこの3つを使えます（親のツールも増えます）。

```json
{ "defaultTools": ["+grep", "+find", "+ls"] }
```

各子のモデル・ツール・出力予算は上記profileで制限します。子の最終出力（失敗時はエラーと部分報告）が8 KiBを超える場合、全文を `os.tmpdir()/pi-cc-subagent/` に保存し、親には先頭約2 KiBと `Full result (N KiB) saved to: <path> — read it only if needed.` の案内だけを返します。前景のツール結果・背景の完了メッセージの両方に適用します。ディレクトリは0700、ファイルは0600で、表示名・時刻・UUIDを使う固有名です。保存に失敗した場合は従来の上限付きインライン出力に戻ります。作成したファイルはセッション終了時に削除します（強制終了時の削除は保証しません）。

UI の `details` には従来どおり子ごとに約48 KiBまでの出力を保持します。親への合計出力も約48 KiBに制限し、切り詰めを表示します。表示履歴は最新80件、各項目1 KiBまでです。完全な子トランスクリプトの保存・再開機能はありません。ツール結果の `details` に表示用の状態を保存するため、親セッションを再開しても完了行を復元できます。

前景実行の使用量は親の Pi に加算。背景実行は加算されず、子のライブ詳細・完了メッセージの `details` で確認します。行に表示するトークン数は Claude Code 同様、最後のモデル応答の入力・キャッシュ・出力合計であり、累積請求トークン数とは異なります。

## 忠実性と制約

履歴内の表示は **2.1.19**、下部エージェント表示は **2.1.63** のコードを参照しています。手元の 2.1.321 はネイティブバイナリで、最新版のソースと比較したものではありません。[参照箇所と検証方法](docs/claude-code-reference.md)に詳細を記載しています。

Pi の拡張 API は別々のツール呼び出しを1行群に統合できないため、並列ツリーは1回の `cc_subagent` の `tasks` 配列内で再現します。バックグラウンド実行と競合ガードは上記の Pi 用実装です。Claude Code の↓の管理画面、エージェント再開、チーム、モデル別バッジ、独自エージェント定義は未実装です。内容の展開には Pi のツール展開機能を使い、応答本文はプレーンテキストです。Claude Code 本体を移植・同梱したものではなく、完全なピクセル一致を保証するものではありません。

背景実行のツール呼び出しは Pi 1.5.1 の内部動作に依存します。親ツールが返った後も `ctx.executeTool()` で権限フックを通しますが、終了済みの親ツールIDと、その時点の最新の親アシスタントメッセージが使われます。返却後に作られた nested-call レコードは回収されず、セッション中に小さなメモリ保持が残ります。また、その呼び出し履歴・使用量は終了済みの親ツール結果には追記されません。Pi 側の将来の変更で再確認が必要な制約です。
