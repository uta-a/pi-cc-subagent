# pi-cc-subagent

Pi 用のサブエージェント拡張。**公式 Claude Code 2.1.19 / 2.1.63 の npm 配布コードを実際に確認**し、サブエージェントのターミナル表示を Pi のレンダラーで再実装しています。拡張の実行に Claude Code の環境や契約は不要です。

## 導入

Pi 1.5.1 で動作確認。

```bash
# このディレクトリで、一度だけ試す
pi -e ./src/index.ts

# GitHub の最新 main を使う（タグ・コミットには固定しない）
# ステータスラインも併せて導入すると縦表示・右寄せ統計が有効になる
pi install git:github.com/uta-a/pi-cc-statusline
pi install git:github.com/uta-a/pi-cc-subagent
```

インストール後は起動中の Pi で `/reload`。既存の `pi-subagents` とツール名が衝突しないよう、`cc_subagent` という名前で登録します。

更新時は次を実行し、Pi で `/reload` します。`latest` というタグではなく、Git の既定ブランチ `main` の最新コミットへ更新する設定です。

```bash
pi update git:github.com/uta-a/pi-cc-statusline
pi update git:github.com/uta-a/pi-cc-subagent
```

## 使い方

```text
/cc-agent Explore 認証処理の入口とセッション管理の流れを調べて
/cc-agent Plan 認証処理のリファクタリング案を作って
/cc-agent general-purpose 指定した不具合を修正してテストして
```

このコマンドは親モデルに `cc_subagent` の呼び出しを依頼します。親モデルがタスクと結果を取りまとめ、サブエージェントは独立した会話履歴で実行します。親のシステム指示、作業ディレクトリ、権限チェックを引き継ぎ、モデルと effort はタスクごとに選択します。会話履歴自体は引き継がないため、タスクには必要な情報を含めてください。

モデルから使う場合：

```json
{
  "description": "認証処理の調査",
  "prompt": "src/auth 配下の認証フローを調査し、関連ファイルと問題点を報告してください。",
  "subagent_type": "Explore"
}
```

並列実行：

```json
{
  "tasks": [
    { "description": "認証処理の調査", "prompt": "認証の入口を調べて", "subagent_type": "Explore" },
    { "description": "テストの調査", "prompt": "認証テストの不足を調べて", "subagent_type": "Explore" }
  ]
}
```

最大8タスク、同時実行4。並列タスクに同じファイルを編集させないでください。`Esc` による親のキャンセルを子のモデル呼び出しとツール呼び出しにも伝播します。

## 表示

```text
● Explore(認証処理の調査) (ctrl+o to expand)
  ⎿  Read(src/auth.ts)
     Read(src/session.ts)
     Search(validateSession)
     +1 more tool use (ctrl+o to expand)

● Explore(認証処理の調査) (ctrl+o to expand)
  ⎿  Done (7 tool uses · 12.4k tokens · 23s)

● Running 2 Explore agents… (ctrl+o to expand)
   ├─ 認証処理の調査 · 7 tool uses · 12.4k tokens
   │  Read(src/auth.ts)
   └─ テストの調査 · 3 tool uses · 8.2k tokens
      Read(test/auth.test.ts)
```

- 通常表示は直近3件の進捗だけ。完了後は統計に折りたたみ。
- `Ctrl+O` で `Prompt:`、実行履歴、`Response:` を展開。キーを変更している場合は実際の設定を表示。
- 低いターミナルでは `In progress…` に省略。
- 背景ボックスは使わず、`●` と `⎿`、並列ツリーのインデントを再現。
- 配色は Pi の現在のテーマを使用。

**API 呼び出しなしのデモ：** `/cc-subagent-demo`。`[demo]` 付きの架空データを履歴に表示します。

## ステータスライン下のエージェント表示

実行中は、ステータスラインの下に親・子エージェントを縦に表示します。MCP など他の拡張ステータスとの間には空行を1行入れます。

```text
Opus … · Context …

● main
○ Explore  ホームの git リポジトリ概要調査                  6s · ↓ 26.4k tokens
○ worker   テストを実行                                  3s · ↑ 2.1k tokens
```

- 選択中の行は白・太字の `●`、他の行は灰色の `○`。子の役割・タスク名・経過時間・トークン数を表示します。
- 統計は実際の描画幅に合わせて右寄せし、長いタスク名を先に省略します。狭い画面では統計を省略します。
- 同種の子は `Explore-2` などで区別。先に始まった子が完了しても、残った子の番号は変わりません。
- 待機中・完了・失敗・中断済みの子は非表示。全実行終了で行を消します。中断要求を受けて終了処理中の子は、処理が戻るまで表示される場合があります。
- 別々の `cc_subagent` 呼び出しも合成し、最大8件と残り件数を表示。
- `ctx.ui.setStatus()` を使用し、既存のフッターや他拡張のステータスは上書きしません。縦表示には、改行対応した `pi-cc-statusline` を併用してください（同プロジェクトの `extension/status-rows.ts`）。Pi 標準フッターは改行を空白に変換するため横表示になります。拡張ステータスを描画しない独自フッターでは表示されません。
- ステータス表示は TUI のみ。通常画面・全画面の両方で確認済みです。

**表示だけ試す：** `/cc-subagent-status-demo`（10秒で消去）。即時消去は `/cc-subagent-status-demo off`。実行中はデモを開始できません。実タスク開始時もデモを消去します。

### ↑↓・Enter の操作

入力欄が空のときに **↓**（または Shift+↓）でエージェント選択に入り、**↑↓** で main／子を移動できます。選択前の ↑ は通常のプロンプト履歴として使えます。入力欄に文章がある場合や、権限確認・別の選択画面にフォーカスがある場合は、その入力操作を奪いません。

- **Enter**：選択した子のライブ詳細を開きます。main ではプレビューを開かず、元の会話へ戻ります。
- 詳細内の **↑↓**：表示対象を切り替えます。main に移動した時点でプレビューを閉じます。
- **PgUp / PgDn**：詳細をスクロールします。
- **Enter / Esc**：詳細を閉じて入力欄へ戻ります。閉じる操作で子を中断しません。
- **`/cc-agents`**：選択中の子、または最初の実行中の子の詳細を開きます。

子の詳細には使用モデル・effort・profile、タスク、現在のモデル待機・ツール実行、活動履歴、生成中の応答、最終結果を表示します。main では通常の Pi の会話をそのまま表示します。完了した子を開いていた場合は最終状態を確認でき、↑↓で現在の実行一覧に戻れます。

公式 2.1.63 の `cSq` / `e16` / `jb` の選択・表示・復帰状態を参考にした **Pi 用の読み取り専用詳細パネル** です。CC のネイティブな会話トランスクリプト差し替え、チーム機能、Escによる子の中断、kill操作は移植していません。画像の縦配置と plain ↑↓ 操作は依頼に合わせた仕様です。

## タスク別のモデル・effortとコスト制御

`model` / `effort` / `profile` は単一タスクにも `tasks` 配列の各項目にも指定できます。未指定時は追加の分類用APIを呼ばず、タスク種別・リスクキーワードと利用可能なモデル一覧で振り分けます。

| profile | 用途・既定 effort | モデルターン上限 | ツール上限 | 1応答 / 累計出力トークン上限 |
|---|---|---:|---:|---:|
| `quick` | 軽い探索・誤字修正、`minimal` | 6 | 12 | 2,048 / 4,096 |
| `balanced` | 通常の実装、`low` | 12 | 24 | 4,096 / 12,000 |
| `deep` | 設計・難しい監査、`medium` | 20 | 48 | 8,192 / 24,000 |

- 自動選択は、quickなら利用可能な Haiku/mini/flash 系、balancedなら親がOpus/軽量系の場合にSonnet系、deepなら親がSonnet/軽量系の場合にOpus系を優先します。現在のproviderを優先し、同じprovider・系統では新しいIDを優先します。GPT等の性能序列が不明なモデルを名前だけで格付けしません。
- 対応モデルがなければ親モデルを維持します。自動選択はセッションの scoped models を尊重します。
- `model: "provider/id"` で明示、`model: "inherit"` で親を維持できます。利用不可・曖昧な明示指定は黙って別モデルへ変更せずエラーにします。
- `effort` は `auto` / `off` / `minimal` / `low` / `medium` / `high`。非推論モデルでは `off`、小さい残り出力予算では推論を切ります。実際のprovider側の対応レベルへの変換はPiに任せます。
- `profile: "auto"` が既定。`Explore` は通常quick、`Plan` はdeep。複雑な監査等はdeepへ切り替えます。必要なら呼び出し側でprofileを明示してください。
- 単価や契約残量をリアルタイム比較する最安保証ではありません。別providerへ自動選択される場合もあります。固定したい場合は `model: "inherit"` を使ってください。

```json
{
  "tasks": [
    { "description": "関連ファイルを探す", "prompt": "関連ファイルだけ報告", "subagent_type": "Explore", "profile": "quick", "effort": "minimal" },
    { "description": "競合状態を検証", "prompt": "競合の再現条件と安全な修正方針を検証", "subagent_type": "Plan", "profile": "deep", "effort": "medium", "model": "inherit" }
  ]
}
```

ツール利用は検索→絞り込んだ範囲の読み取りを優先し、独立した読み取りを1モデル応答にまとめ、重複探索・不要な検証の再実行を避けるよう指示します。ツール結果はprofileごとに4/8/12 KiBに制限します。結果を無条件キャッシュして権限チェックを飛ばすことはしません。予算到達時は未完了として返し、勝手な再試行・モデル昇格はしません。

UIの通常更新は詳細表示・スナップショットとも毎秒1回に抑え（開始・終了などの状態変化は即時反映）、フッターの時計更新だけでは履歴を複製しません。mainの本文を別途追跡・描画する処理も省いています。親のシステム指示は安全性のため切り捨てません。

## 実行・安全性の範囲

| 種別 | 使用可能なツール |
|---|---|
| `Explore` / `Plan` | `read`, `grep`, `find`, `ls` |
| `general-purpose`（既定） | 上記 + `bash`, `write`, `edit` |

親で利用可能なツールとの積集合だけを公開します。モデルが未公開ツールを要求しても実行しません。`ctx.executeTool()` を通すため、親の引数検証、権限フック、ファイル変更キューを維持します。`general-purpose` は通常の Pi と同じユーザー権限で動き、サンドボックスではありません。

各子のモデル・ツール・出力予算は上記profileで制限します。表示用出力は子ごとに約48 KiB、親への合計出力も約48 KiBに制限し、切り詰めを表示します。表示履歴は最新80件、各項目1 KiBまでです。完全な子トランスクリプトの保存・再開機能はありません。ツール結果の `details` に表示用の状態を保存するため、親セッションを再開しても完了行を復元できます。

使用量は親の Pi に加算。行に表示するトークン数は Claude Code 同様、最後のモデル応答の入力・キャッシュ・出力合計であり、累積請求トークン数とは異なります。

## 忠実性と制約

履歴内の表示は **2.1.19**、下部エージェント表示は **2.1.63** のコードを参照しています。手元の 2.1.321 はネイティブバイナリで、最新版のソースと比較したものではありません。[参照箇所と検証方法](docs/claude-code-reference.md)に詳細を記載しています。

Pi の拡張 API は別々のツール呼び出しを1行群に統合できないため、並列ツリーは1回の `cc_subagent` の `tasks` 配列内で再現します。Claude Code のバックグラウンド実行、↓の管理画面、エージェント再開、チーム、モデル別バッジ、独自エージェント定義は未実装です。内容の展開には Pi のツール展開機能を使い、応答本文はプレーンテキストです。Claude Code 本体を移植・同梱したものではなく、完全なピクセル一致を保証するものではありません。
